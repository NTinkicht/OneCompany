# References and provenance policy

OneCompany distinguishes third-party inspiration from product authority.
Historical development observations are retained in Git history, but no
previous product, repository, hosted environment or case-study snapshot
is a required dependency of the reusable distribution.

## General engineering references

- GitHub Actions workflow syntax: https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax
- GitHub Actions troubleshooting: https://docs.github.com/en/actions/how-tos/troubleshoot-workflows
- GitHub scheduled workflows: https://docs.github.com/en/actions/tutorials/manage-your-work/schedule-issue-creation
- OpenAI scheduled tasks: https://help.openai.com/en/articles/10291617
- OpenAI connected GitHub: https://help.openai.com/en/articles/11145903-connecting-github-to-chatgpt-drease

Provider limits and available functionality change; reverify external docs
at the deployment's actual time. The product does not treat an example
account's entitlement, permissions or spend limit as universal.

## Reusable ideas (not service dependencies)

Aligned autonomy, cross-cutting technical standards, fail-closed
permissioning, source-controlled reproducibility, bounded Work Units,
immutable evidence, and human-override paths are implemented through
OneCompany's **own reviewed schemas and code**. External publications or
optional agent libraries do not create operating authority.

## Attribution policy

Retain applicable copyright/license notices for any substantive external
code or text copied into the distribution. Generic ideas are adapted as
OneCompany-native implementations, not imported as a live dependency.
Exact historical implementation origins can be audited in prior Git
commits without copying project-specific identities into new installs.
