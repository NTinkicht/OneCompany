# Definition of Ready

A Work Unit may enter implementation only when the assurance level appropriate to its risk is satisfied.

Required: objective and value; explicit scope and non-goals; approved traceable requirements; testable acceptance criteria; dependency state; initial risk assessment; architecture/design impact; security/privacy/data/safety/UX/operations impacts; required test families; documentation impact; observability expectations; rollout/rollback approach when applicable; named implementer lease path and independent gate expectation.

Unknowns are allowed only when explicitly converted into discovery tasks or risks. `We'll figure it out while coding` is not a readiness strategy for material uncertainty.
