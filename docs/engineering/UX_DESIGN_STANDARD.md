# UX and Design Standard

User-facing software requires deliberate interaction design rather than per-PR improvisation.

Projects should declare design tokens, reusable components, typography/spacing, responsive breakpoints and interaction conventions. User journeys cover normal, empty, loading, error, offline/degraded and success states as applicable.

Accessibility is a quality requirement. Relevant projects test keyboard interaction, semantic structure, focus, labels, contrast and responsive behaviour, supplemented by manual review where automated checks are insufficient. Significant UI changes should use visual regression or equivalent evidence.
